## 2. Implementation Scope Breakdown

### A. IMPLEMENTED (Phase E.7.4 Deliverables)
1. **PlanExecutor (`server/music_daemon/planner/executor.py`)**:
   - Accepts only `ValidationResult` (or validates raw plans via `PlanValidator` before dispatch).
   - Rejects unvalidated or failed plans with `ErrorCode.PLAN_NOT_VALIDATED`.
   - Sequential step execution with per-step execution status and audit trail.
   - Re-evaluates preconditions against fresh `RoomState` immediately before physical mutation.
   - Re-checks idempotency against fresh `RoomState` to skip redundant actions.
   - Dispatches capabilities directly through established hardware controllers (`ProjectorController`, `AcController`, `PcController`, `FireTvController`, `SmartRoomOrchestrator`, `FireTvService`).
   - Physical read-back verification polling with bounded timeouts (`5.0s` default).
   - Enforces `FailurePolicy` (`ABORT_PLAN`, `CONTINUE_BEST_EFFORT`, `EXECUTE_FALLBACK`).
   - Accurately captures partial execution states (`OverallExecutionStatus.PARTIAL_SUCCESS`).
2. **Execution Models & Status Hierarchy (`server/music_daemon/planner/models.py`)**:
   - `ExecutionStatus`: `PENDING`, `SKIPPED`, `PRECONDITION_FAILED`, `UNKNOWN_STATE`, `STALE_STATE`, `DISPATCHED`, `VERIFIED`, `FAILED`, `TIMEOUT`.
   - `OverallExecutionStatus`: `PENDING`, `SUCCESS`, `PARTIAL_SUCCESS`, `FAILED`, `ABORTED`, `SKIPPED`.
   - `StepExecutionResult`: Step ID, capability, parameters, status, timestamps, precondition result, dispatch result, read-back evidence, verified flag, error codes.
   - `ExecutionResult`: Execution ID, plan ID, user request, intent, timing, overall status, step list, verified/skipped/failed counts, failure codes.
3. **Deterministic Error Codes (`server/music_daemon/planner/errors.py`)**:
   - Added `PLAN_NOT_VALIDATED`, `DISPATCH_FAILED`, `READBACK_TIMEOUT`, `READBACK_MISMATCH`, `EXECUTION_ABORTED`, `CONTROLLER_UNAVAILABLE`.
4. **Execution REST API (`server/music_daemon/main.py`)**:
   - `POST /api/planner/execute`: Translates intent $\to$ generates plan $\to$ enforces `PlanValidator` $\to$ dispatches via `PlanExecutor` $\to$ returns full `ExecutionResult`.
   - Rejects unvalidated plans before hardware mutation occurs.
5. **Comprehensive Test Suite (`server/music_daemon/tests/test_planner_executor.py`)**:
   - 11 comprehensive unit and contract tests verifying validation boundary, precondition re-evaluation, idempotency skipping, multi-subsystem dispatch, read-back timeout handling, failure policies, and REST execution endpoint.

## 5. Precondition & Freshness Enforcement Prior to Mutation

Before every atomic physical capability dispatch:
1. `PlanExecutor` queries fresh `RoomState` from `RoomStateAggregator`.
2. Evaluates all preconditions against live telemetry using `RestrictedPreconditionEvaluator`.
3. If any field has `Provenance.UNKNOWN`, returns `ExecutionStatus.UNKNOWN_STATE` (fails closed).
4. If telemetry freshness exceeds TTL ($t > \text{TTL}$), returns `ExecutionStatus.STALE_STATE` (fails closed).
5. If precondition expression evaluates to `False`, returns `ExecutionStatus.PRECONDITION_FAILED` (fails closed).

## 6. Physical Read-Back Verification Polling

Every state-changing physical action requires authoritative verification through live `RoomState`:
- **AC Subsystem**:
  - `AC_SET_TEMPERATURE`: Polls `RoomState.ac.target_temperature == target` (fresh observed state).
  - `AC_POWER_ON` / `AC_POWER_OFF`: Polls `RoomState.ac.power == True/False`.
  - `AC_SET_MODE`: Polls `RoomState.ac.mode == target`.
  - `AC_SET_FAN`: Polls `RoomState.ac.fan_speed == target`.
- **PC Subsystem**:
  - `PC_SET_VOLUME`: Polls `RoomState.pc.master_volume == target`.
  - `PC_MUTE` / `PC_UNMUTE`: Polls `RoomState.pc.is_muted == True/False`.
- **Projector Subsystem**:
  - `PROJECTOR_POWER_WAKE`: Polls `RoomState.projector.power == True`.
  - `PROJECTOR_POWER_SLEEP`: Polls `RoomState.projector.power == False`.
  - `PROJECTOR_SWITCH_HDMI1`: Polls `RoomState.projector.input_source == "HDMI_1"`.
  - `PROJECTOR_SET_BRIGHTNESS`: Polls `RoomState.projector.brightness == target`.
- **Soundbar & Routing**:
  - `SOUNDBAR_ROUTE_TO_FIRE_TV`: Polls `RoomState.soundbar.current_owner == "FIRE_TV"`.
  - `SOUNDBAR_ROUTE_TO_PC`: Polls `RoomState.soundbar.current_owner == "PC"`.
  - `FIRE_TV_BT_CONNECT_SOUNDBAR`: Polls `RoomState.fire_tv.soundbar_connected == True`.
