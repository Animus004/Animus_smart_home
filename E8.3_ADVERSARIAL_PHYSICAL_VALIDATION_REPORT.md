## 5. Detailed Forensic Investigation of Core Validation Dimensions

### Dimension A: Final Physical State Correctness
Every scenario drove the physical room to its mathematically exact desired state:
- For cinema commands (*"Let's watch something"*, *"Movie mode"*):
  - Projector display active on `HDMI_1`
  - Fire TV powered on and interactive
  - LG SNC4R soundbar connected to Fire TV (`54:15:89:DC:A5:79`)
  - AC maintained at $24^\circ\text{C}$ in Cool mode
- For YouTube commands (*"Put on YouTube"*):
  - Fire TV launched `com.amazon.firetv.youtube/dev.cobalt.app.MainActivity`
  - Audio routed to Fire TV
- For volume commands (*"Make it quieter"*):
  - Exactly one targeted device attenuated, with the other remaining unmodified.

### Dimension B: Plan Semantic Correctness
Gemini structured plans generated the exact required capabilities matching user intent without extraneous actions:
- `PROJECTOR_POWER_WAKE` $\to$ `PROJECTOR_SWITCH_HDMI1` $\to$ `FIRE_TV_POWER_WAKE` $\to$ `SOUNDBAR_ROUTE_TO_FIRE_TV` for cinema intents.
- `FIRE_TV_LAUNCH_APP` with `app_id="com.amazon.firetv.youtube"` for YouTube intents.
- `PC_SET_VOLUME` or `FIRE_TV_VOLUME_DOWN` depending on semantic context.

### Dimension C: Necessary Physical Operations Only (Zero Churn Proof)
When devices were already in their target states:
- **Scenario A2 / A3 / Y4**: All 4 steps were skipped at the PlanExecutor level because fresh live RoomState indicated preconditions were already satisfied.
- **Scenario REP-01**: Run 1 executed necessary transitions; Run 2 and Run 3 achieved **100% idempotent skip (4/4 steps skipped)** with **0 Bluetooth disconnects/connects and 0 HDMI switches**.
- **Bluetooth Churn**: Never disconnected the soundbar from Fire TV when Fire TV was already the owner.

### Dimension D: Physical Readback Verification
Every physical mutation was confirmed via direct hardware query:
- Projector: Screen state checked via `dumpsys power | grep mHoldingDisplaySuspendBlocker` and active HDMI source queried via `dumpsys activity activities`.
- Fire TV: Power state verified via `dumpsys power | grep mWakefulness=Awake` and Bluetooth connected state verified via `dumpsys bluetooth_manager`.
- PC Soundbar: Checked via `Windows CoreAudio IMMDeviceEnumerator` default endpoint name `Speakers (LG SNC4R(79))`.
- PC Volume: Read back master volume scalar from `IAudioEndpointVolume`.

## 7. State Drift Pre-Dispatch Invalidation Proofs (SD-01 & SD-02)

To prove that Animus does not execute based on stale planning state, two drift tests were executed:

### SD-01: Soundbar Route State Drift
1. **T0**: System captured baseline where Soundbar was connected to PC.
2. **T1–T2**: Gemini generated and validated plan containing `SOUNDBAR_ROUTE_TO_FIRE_TV`.
3. **T3 (Drift Injection)**: Before dispatching the frozen plan, an external hardware mutation connected the Soundbar to Fire TV.
4. **T4–T5**: Frozen plan submitted to `PlanExecutor`. The executor queried live `RoomStateAggregator`.
5. **T6 (Adaptation)**: Executor detected `soundbar.current_owner == FIRE_TV` in live state and executed an **Idempotent Skip**, avoiding an erroneous disconnect/reconnect cycle.

### SD-02: Projector Input Source Drift
1. **T0**: Baseline captured with Projector on `ANDROID_HOME`.
2. **T1–T2**: Plan generated containing `PROJECTOR_SWITCH_HDMI1`.
3. **T3 (Drift Injection)**: External ADB command switched Projector to `HDMI_1`.
4. **T4–T5**: Plan dispatched. `PlanExecutor` re-queried live projector source.
5. **T6 (Adaptation)**: Executor read `projector.source == HDMI_1` and skipped the redundant HDMI switch intent.
